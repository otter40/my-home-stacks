# spec.md — 功能需求规格

## 1. 项目背景

参考现有 Notion 工作区"👑 王家今天吃什么"，将其核心功能改造为微信小程序。
目标：帮助家庭记录菜谱、管理冰箱库存、自动推荐今天能做什么，并生成购物清单。

---

## 2. 核心约束

- **平台**：微信小程序
- **开发模板**：TS-基础模版（TypeScript，普通渲染模式，不使用 Skyline，不使用 Sass/Less）
- **数据存储**：本地存储（`wx.setStorageSync` / `wx.getStorageSync`），不接云开发，不接后端服务器
- **数据隔离**：每台设备数据独立，互不共享
- **无外部依赖**：不依赖 Notion，不依赖外部账号体系，完全独立运行
- **操作端**：用户全程只用手机操作

## 4. 数据结构

```typescript
// 菜谱
interface Recipe {
  id: string;
  name: string;             // 菜名
  category: string;         // 分类（荤菜/素菜/汤羹/主食/其他，可自定义新增）
  ingredients: Ingredient[]; // 所需食材列表
  steps?: string;            // 做法（可选，纯文本）
  isToday: boolean;          // 是否在"今天吃"列表中
}

// 菜谱中的食材条目
interface Ingredient {
  name: string;  // 食材名称，需与 InventoryItem.name 精确匹配
  qty: number;   // 数量
  unit: string;  // 单位（个/g/把/勺 等）
}

// 库存（食材库与库存合并为一张表）
interface InventoryItem {
  id: string;
  name: string;           // 食材名称
  qty: number;            // 当前数量
  unit: string;           // 单位
  location: string;       // 存放位置（冷藏/冷冻/常温/调料区，可自定义新增）
  expiry?: string | null;  // 到期日，ISO 日期字符串，可选
  needBuy: boolean;        // 是否标记"需要购买"
}

// 购物袋手动添加项
interface ShoppingItem {
  id: string;
  name: string;
  qty?: number;
  unit?: string;
}

// 本地存储 key 汇总
// storage key: "recipes"       → Recipe[]
// storage key: "inventory"     → InventoryItem[]
// storage key: "shoppingItems" → ShoppingItem[]
// storage key: "customCategories"  → string[]  （用户自定义菜谱分类）
// storage key: "customLocations"   → string[]  （用户自定义存放位置）
```

## 6. 功能详细说明

### 6.1 今天吃

- 显示所有 `isToday === true` 的菜谱卡片（菜名、分类标签、食材简要列表）
- 每张卡片提供「✅ 做完了」按钮 → 将该菜的 `isToday` 设为 `false`，从列表移除
- 列表为空时显示空状态提示，引导用户前往"冰箱能做什么"或"菜谱库"

### 6.2 冰箱能做什么

**匹配规则**：食材名称去除首尾空格后字符串精确匹配（不区分大小写）

**分组展示**：
- **可以做**：菜谱的所有 `ingredients` 在库存中均有对应记录且 `qty > 0`
- **差一点点**（优化项）：菜谱中有 1–2 项食材库存不足或不存在，列出缺少的食材名称

每张"可以做"卡片提供「加入今天吃」按钮 → 设置 `isToday = true`

### 6.3 菜谱库

- 列表展示所有菜谱，支持**按分类筛选**和**按菜名搜索**
- **新增 / 编辑**菜谱表单字段：
  - 菜名（必填）
  - 分类（下拉选择，含默认分类 + 用户自定义分类，支持新增自定义分类）
  - 食材列表（动态行，每行：食材名称 + 数量 + 单位，支持增删行）
  - 做法（可选，多行文本）
- **删除**菜谱需二次确认（`wx.showModal`）

### 6.4 库存

- 按**存放位置**分组展示（冷藏 / 冷冻 / 常温 / 调料区 / 用户自定义）
- 每项功能：
  - 数量快捷加减按钮（`+` / `-`，数量最小为 0）
  - 「需要购买」开关（切换 `needBuy`）
  - 保质期显示：
    - 3 天内到期 → 橙色警告标签
    - 已过期 → 红色标签
    - 正常 → 不特别标注
  - 编辑（名称、数量、单位、位置、保质期）
  - 删除（需二次确认）
- **新增食材**字段：名称（必填）、数量、单位、存放位置、保质期（可选）
- 存放位置支持用户自定义新增

### 6.5 购物袋

**自动汇总项**（只读，不可手动删除）来源：
1. 所有 `isToday === true` 的菜谱中，`ingredients` 在库存中不存在或 `qty <= 0` 的食材
2. 库存中 `needBuy === true` 的食材

以上按**食材名称去重合并**展示。

**手动添加项**（`ShoppingItem[]`）：用户可直接添加任意物品，不必关联菜谱或库存。

**「已购买」操作逻辑**：
- 若该食材在库存中已存在 → 数量增加（增加值取菜谱所需数量，无关联则 +1），并将 `needBuy` 设为 `false`
- 若库存中不存在 → 新建库存记录（数量默认为所需数量或 1，位置默认为"未分类"，用户后续可编辑）
- 操作完成后该项从购物袋移除

## 7. 设计规范

- **风格**：温暖家庭感，"厨房手账"风格
- **配色**：米白底色（`#FBF8F3`）为主，橙色（`#F4845F`）/ 绿色（`#6DBF86`）/ 黄色（`#F9C74F`）作为分类和状态强调色
- **卡片**：圆角（`border-radius: 12px`）、轻阴影（`box-shadow: 0 2px 8px rgba(0,0,0,0.06)`）
- **分类标签**：不同分类用不同颜色标签区分
- **状态提示**：到期警告、待购标记等用醒目但不刺眼的小标签或彩色圆点
- **交互**：以点按、勾选、加减按钮为主，减少长文本输入场景
