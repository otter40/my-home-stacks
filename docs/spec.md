# spec.md — 功能需求规格（v2）

## 1. 项目背景

参考现有 Notion 工作区"👑 王家今天吃什么"，将其核心功能改造为微信小程序。
目标：帮助家庭维护**食材库**、记录**菜谱**、管理冰箱**库存**，自动推荐今天能做什么，并生成**购物清单**。

> v2 相比 v1 的主要变化：食材库与库存拆分并完整关联、菜谱分类升级为多字段、今天吃与冰箱合并进首页、UI 改为 Notion 浅色风、新增"我的"管理页。

---

## 2. 核心约束

- **平台**：微信小程序，TS-基础模版，普通渲染（非 Skyline），原生 wxss（不使用 Sass/Less）
- **数据存储**：本地存储（`wx.setStorageSync` / `wx.getStorageSync`），不接云开发与后端
- **数据隔离**：每台设备数据独立
- **完全独立运行**：无账号体系、无外部依赖、全程手机操作
- **数据模型**：三张核心表（食材库 / 菜谱 / 库存）完整关联，菜谱与库存通过 `ingredientId` 引用食材库

## 4. 数据结构

```typescript
// 🥕 食材库目录条目
interface Ingredient {
  id: string;
  name: string;
  category: string;        // 食材分类（单选，见 §5）
  defaultUnit?: string;    // 默认单位（建库存/菜谱时带出，可选）
}

// 菜谱中的食材引用行（引用食材库）
interface RecipeIngredient {
  ingredientId: string;    // 引用 Ingredient.id
  qty: number;
  unit: string;
  main: boolean;           // 是否主料（冰箱建议只看主料；调味/香料/佐料默认辅料）
}

// 📖 菜谱
interface Recipe {
  id: string;
  name: string;
  types: string[];         // 类型（多选，见 §5）
  cuisines: string[];      // 菜系（多选，见 §5）
  prep: string;            // 提前备菜（单选，见 §5）
  ingredients: RecipeIngredient[];
  steps?: string;          // 做法（可选）
  isToday: boolean;        // 是否在"今天想吃"中
}

// 🛖 库存（家里实际存货）
interface StockItem {
  id: string;
  ingredientId: string;    // 引用 Ingredient.id
  qty: number;
  unit: string;
  location: string;        // 存放位置（单选，可自定义）
  expiry?: string | null;  // 到期日 ISO（YYYY-MM-DD），可选
  statuses: string[];      // 状态（多选，见 §5）
  needBuy: boolean;        // 标记需要购买
}

// 🛒 购物袋手动添加项
interface ShoppingItem {
  id: string;
  name: string;
  qty?: number;
  unit?: string;
  ingredientId?: string;   // 若关联到食材库（可选）
}

// 做菜历史（用于使用统计）
interface CookRecord {
  id: string;
  recipeId: string;
  name: string;            // 冗余菜名，避免菜谱删除后丢失
  date: string;            // ISO 日期 YYYY-MM-DD
}

// 用户自定义选项（分类/标签管理）
interface CustomOptions {
  recipeTypes: string[];
  cuisines: string[];
  ingredientCategories: string[];
  locations: string[];
  stockStatuses: string[];
}
```

| 食材分类 | 食材库 | 单选 | 🥩肉、🥬蔬菜、🐟海鲜、🥚蛋奶、🫘豆制品、🍚主食/谷物、🍄菌菇、🧂调味、🌿香料、🧄佐料、🥫罐头/干货、🥤饮品、🍎水果、🥜坚果/种子、🧊冷冻/速冻、🍰烘焙/甜品原料、🥗加工食品/半成品、🍵茶/冲泡饮品、🍿零食 |
| 存放位置 | 库存 | 单选 | 冷藏、冷冻、常温、调料区 |

**主料默认规则**：新增菜谱食材时，若所选食材的分类含「调味」「香料」「佐料」，`main` 默认 false（辅料），否则默认 true（主料）。用户可逐条手动调整。

## 6. 功能详细说明

### 6.1 首页（🏠）

自上而下三段，单页滚动：

1. **欢迎条**：应用名 + 今天日期 + 一句轻提示（无账号，纯问候）。
2. **今天想吃**：展示所有 `isToday === true` 的菜谱卡片（菜名 + 类型/菜系标签 + 主料一览）。
   - 每张卡片「✅ 做完了」→ 自动**从库存扣减该菜主+辅料用量**（见 §6.6），写入做菜历史，`isToday` 置 false 移出。
   - 列表为空时，本段折叠为一句引导。
3. **冰箱建议**（始终显示在下方）：基于库存计算（只看主料，见 §6.6），分「可以做 / 差一点点」两组；可以做的卡片提供「加入想吃」按钮（`isToday=true`）。
4. **购物袋摘要**：显示购物袋条目数 + 前几项，「去购物袋 ›」入口跳转 `pages/shopping/shopping`。

### 6.2 库存（🧊）

- 按**存放位置**分组展示（可折叠）。
- 每项显示：食材名（取自食材库）+ 数量（±快捷按钮，最小 0）+ 单位 + 保质期标签（已过期/即将到期）+ 状态多选标签（如 🔒已开封）。
- **「需要购买」改为按钮式**（点按切换 `needBuy`，选中/未选中两态，替换原 switch）。
- 新增/编辑：选择食材库中的食材（或现场新建食材）、数量、单位、位置（支持新增）、保质期、状态（多选）。
- 删除：二次确认。

### 6.3 菜谱（📖）

- 列表展示所有菜谱，支持按**类型 / 菜系**筛选 + 按菜名搜索。
- 卡片显示：菜名、类型/菜系标签、提前备菜、主料一览，并提供**「加入今天吃」按钮**（直接置 `isToday=true`）。
- 新增/编辑表单：菜名、类型（多选）、菜系（多选）、提前备菜（单选）、食材列表（从食材库选择 + 数量 + 单位 + 主料开关，动态增删行）、做法。
- 删除：二次确认。

### 6.4 食材（🥕）

- 按**食材分类**分组罗列食材库所有食材。
- 点击某食材查看详情：当前库存合计、**反向关联**——哪些菜谱用到它。
- 新增/编辑食材：名称、分类（支持新增）、默认单位。
- 删除：二次确认；若被库存或菜谱引用需提示（阻止或级联，见 architecture）。

### 6.5 购物袋（🛒，子页面）

- **自动汇总项**（只读）来源：① 所有 `isToday` 菜谱中库存不足的食材；② 库存中 `needBuy` 的食材。按食材去重合并。
- **手动添加项**：名称（必填）+ 数量 + 单位。
- **「已购买」**：更新/新建库存（关联到食材库；手动项若无对应食材则在食材库新建），移除该项，轻提示。
- 手动项支持删除（二次确认）。

### 6.6 核心算法

**冰箱建议（只看主料）**：对每个菜谱，取 `ingredients` 中 `main === true` 的项，按 `ingredientId` 求库存合计 qty，合计 > 0 视为满足。缺 0 项=可以做，缺 1–2 项=差一点点，缺 ≥3 项=不展示。辅料缺失不影响判定（卡片可浅色提示）。

**做完了扣减库存**：遍历该菜全部食材（主+辅），按 `ingredientId` 找库存条目，按到期日升序（无到期日排最后）依次扣减，扣到 0 为止；库存不足则扣光。完成后写入 `CookRecord`。

**已购买入库**：自动项带 `ingredientId`，库存有该食材则加量、`needBuy` 置 false；无则新建库存条目。手动项无 `ingredientId` 时，按名称在食材库查找，找不到则新建食材（分类默认未分类）后再建库存。

### 6.7 我的（👤）

- **数据备份**：导出全部数据为 JSON 文本（可复制）；粘贴 JSON 导入覆盖。
- **分类/标签管理**：增删自定义的菜谱类型、菜系、食材分类、存放位置、库存状态。
- **清空/重置**：一键清空全部数据，或恢复到示例 seed（均二次确认）。
- **使用统计**：基于 `CookRecord`，展示本周/本月做过的菜、高频菜等简单统计。

## 7. 设计规范（Notion 浅色风）

- **整体**：白 / 极浅灰底，细灰分割线，黑灰文字，弱化的强调色，大量留白，emoji 作为分类图标。
- **配色**：底 `#FFFFFF` / `#F7F7F5`，文字 `#37352F`，次要文字 `#9B9A97`，分割线 `#EAE9E6`，强调 `#2383E2`（蓝）/ 状态色克制使用。
- **列表/卡片**：弱边框或仅分割线，少阴影，圆角小（6–8px），类数据库的行式排版。
- **标签**：Notion chip 风（浅底 + 深字 + 小圆角），不同分类用低饱和底色。
- **交互**：以点按、勾选、加减、chip 多选为主，减少长文本输入。
